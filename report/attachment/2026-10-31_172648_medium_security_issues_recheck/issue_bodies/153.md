## 概要

Unix で node 鍵を読むとき、`symlink_metadata` で通常のファイルであることを確かめた後、path を指定し直して権限の修復（chmod 0600）と読み取りをしています。検査と操作が同じ file descriptor に結び付いていないため、親ディレクトリを変更できる別のローカルユーザーが検査の直後に entry を symlink に差し替えると、別のファイルの権限が変わったり、別のファイルを鍵として読んだりします。

## 該当箇所（`007d052d8` 時点）

## 期待する動作

`O_NOFOLLOW` で開いた descriptor に対して、file type の確認、権限の修復（`fchmod`）、読み取りを行う。検査の後に symlink へ差し替えられても、別のファイルの chmod や読み取りは起きない。通常の private なディレクトリでの既存鍵の読み取りと、0600 への修復は今までどおり行う。
