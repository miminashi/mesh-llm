## 概要

plugin の HTTP endpoint の address に先頭の空白があると、health check や転送では URL parser が空白を取り除いて通常の URL として扱いますが、metrics には元の文字列のまま記録されます。metrics の秘匿処理は、文字列の 0 文字目から `http://` か `https://` で始まるときだけ働くため、userinfo や token の query がそのまま metrics の label に残ります。この label は、trusted-local の制限がない `GET /api/status` から読めます。

## 期待する動作

metrics の label を作る前に、HTTP URL の正規化と秘匿の規則を揃える（先頭・末尾の空白を取ってから判定する、または `redact_urls_in_text` を使う）。先頭に空白がある HTTP URL でも、userinfo と秘密の query は snapshot に出さない。通常・大文字の scheme での既存の秘匿と、失敗した attempt の秘匿は今までどおり行い、local・remote の target label は書き換えない。
