## 概要

HF の cache への取得は、HEAD で得た ETag と commit で既存の partial file を選びますが、続く GET（Range 付き）も、commit に固定していない元の revision URL へ送ります。206 応答の Content-Range しか確かめず、GET 応答の ETag や commit は HEAD と照合しません。HEAD と GET の間に branch が更新されると、古い内容の先頭に新しいファイルの後半をつないだものを、古い commit の cache として確定してしまいます。

- [`download.rs:537-541`](https://github.com/miminashi/mesh-llm/blob/007d052d8/skippy/crates/skippy-hf-hub/src/repository/download.rs#L537-L541): HEAD の ETag と commit は `admit_etag`・`admit_commit` で検査するが、GET 側では照合しない
- [`download.rs:729-733`](https://github.com/miminashi/mesh-llm/blob/007d052d8/skippy/crates/skippy-hf-hub/src/repository/download.rs#L729-L733): resume を採るかどうかは、206 かつ `content_range_matches` だけで決める
- [`download.rs:759-761`](https://github.com/miminashi/mesh-llm/blob/007d052d8/skippy/crates/skippy-hf-hub/src/repository/download.rs#L759-L761): GET は `Range` だけを付けて送り、`If-Range` は付けない
- [`download.rs:1905-1940`](https://github.com/miminashi/mesh-llm/blob/007d052d8/skippy/crates/skippy-hf-hub/src/repository/download.rs#L1905-L1940): テストサーバはどの応答でも同じ ETag と commit を返すため、identity が変わる場合のテストがない

## 期待する動作

GET を、解決済みで変わらない commit の URL に固定する。または `If-Range` を付け、応答の ETag と commit を HEAD と照合する。identity が変わっていたら、既存の partial file を混ぜずに最初から取り直す。同じ artifact での通常の resume と、不正な range からの取り直しは今までどおり行う。
