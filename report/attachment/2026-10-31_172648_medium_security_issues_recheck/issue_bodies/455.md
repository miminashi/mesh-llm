## 概要

agentic replay の自動修復（repair）では、修復候補が「検証用のファイル」を変更していないかを、root 直下の `.github .agents scripts evals ci` だけで確かめています。しかし、修復後の再検証は `cargo xtool automation replay-matrix ...` で動き、候補の作業ツリーの `tools/xtask` をビルドして実行し、`skippy/evals/` の benchmark 設定も読みます。修復候補がこれらを変更しても保護の検査を通るため、修復される側が自分を検証する仕組みを書き換えられます。

## 該当箇所（`007d052d8` 時点）

- [`scripts/agentic-replay-repair.sh:95-99`](https://github.com/miminashi/mesh-llm/blob/007d052d8/scripts/agentic-replay-repair.sh#L95-L99): repair 側の検査は `git diff --cached --quiet "$BASE_SHA" -- .github .agents scripts evals ci` だけ
- [`.github/workflows/agentic-replay-nightly.yml:337`](https://github.com/miminashi/mesh-llm/blob/007d052d8/.github/workflows/agentic-replay-nightly.yml#L337): 公開前の検査も同じ pathspec
- [`scripts/agentic-replay-repair.sh:111-123`](https://github.com/miminashi/mesh-llm/blob/007d052d8/scripts/agentic-replay-repair.sh#L111-L123): 候補を commit した後に、候補のツリーで `cargo xtool automation replay-matrix export/pins` を実行し、`skippy/evals/skippy-competitive-benchmark.json` を読む
- [`.cargo/config.toml:5`](https://github.com/miminashi/mesh-llm/blob/007d052d8/.cargo/config.toml#L5): `xtool = "run --locked -p xtask --"` なので、`tools/xtask` は候補のツリーからビルドされる

## 期待する動作

再検証で実行・参照するファイル（少なくとも `tools/xtask/`、`.cargo/`、`skippy/evals/`、`mesh/evals/`）を保護対象に含め、repair 側と publisher 側で同じ範囲を検査する。できれば、検証器は修復候補から変更できない状態（base の commit からビルドしたもの）で動かす。許可された製品コードの修正は、今までどおり再検証できる。
