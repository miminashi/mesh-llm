## 概要

release の直接 packaging（precomposed product を使わない経路）は、選んだ native runtime を bundle にコピーした後、今のファイルの中身から新しい product hash を作ります。runtime の manifest に記録された checksum と一致するかを先に確かめないため、壊れた、または書き換えられた library を含む runtime を、正しい digest 付きの新しい product として出荷できてしまいます。precomposed の経路では、同じ検査をしています。

## 該当箇所（`007d052d8` 時点）

- [`mesh/scripts/package-release.sh:620-629`](https://github.com/miminashi/mesh-llm/blob/007d052d8/mesh/scripts/package-release.sh#L620-L629): 直接の経路は `select_native_runtime_dir` で選んだ runtime を `cp -R` し、検査をせずに `write_product_manifest` へ進む
- [`mesh/scripts/package-release.sh:141-146`](https://github.com/miminashi/mesh-llm/blob/007d052d8/mesh/scripts/package-release.sh#L141-L146): runtime の選択は `native select-runtime` に任せている。これは checksum を確かめない
- [`mesh/scripts/package-release.sh:495-502`](https://github.com/miminashi/mesh-llm/blob/007d052d8/mesh/scripts/package-release.sh#L495-L502): precomposed の経路は `verify-native-runtime-package.sh` で runtime を検査してから `product compose --check` を行う
- [`tools/xtask/src/product/compose.rs:98-99`](https://github.com/miminashi/mesh-llm/blob/007d052d8/tools/xtask/src/product/compose.rs#L98-L99): 今の tree から `tree_sha256` で新しい digest を作る。runtime manifest の checksum とは照合しない

## 期待する動作

直接の経路でも、選んだ runtime を既存の `verify-native-runtime-package.sh` で検査してから、コピーと product manifest の生成に進む。checksum が合わない場合は、コピーや manifest の生成より前に失敗する。正しい runtime での直接 packaging と、precomposed の経路の動作は変えない。
